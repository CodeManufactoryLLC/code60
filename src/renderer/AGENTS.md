# Renderer

`src/renderer` is the React interface, built by Vite into `dist/renderer`.

- Reach the main process only through `window.desktop`. Import only types from `core`, and nothing from Node.js or Electron.
- Render agent output, prompts, and diffs as text. Never use `dangerouslySetInnerHTML` or load remote content; the Content Security Policy forbids it.
- Merge updates by revision with `applyUpdate`, so reloads and startup never lose or duplicate events.
- Show status as text, not only as color. Keep controls labelled, keyboard reachable, and their shortcuts visible.
- Support Light, Dark, and System appearance, and the opt-in Signal colors (`data-signals`), with the CSS variables in `style.css`. Light uses white surfaces with subtle borders and restrained shadows to distinguish them, with teal actions (`#43b3ae`) and pale viridian hover fills; selection uses neutral gray; saved Paper selections migrate to Light. Dark and System dark use dark steel-gray (`#242b33`) wherever Light uses white for neutral resting surfaces, with white text, `#aaaaaa` muted text, `#414b56` subtle borders, `#888888` control borders, and `#323c46` selected fills. Preserve gold actions, green hover, colored messages, focus colors, and opt-in signals; separate fields and controls with fine borders and keep disabled stripes transparent. The Code60 wordmark’s colored 60 block has a small upper-right, 45-degree chamfer. The main Chat composer has a 24px upper-right bevel and a compact, centered drop shadow only while focus is inside it: viridian (`#40826d`) in Light and yellow (`--primary`) in Dark and System dark. Keep its border transparent and suppress its ordinary focus outline without shifting layout; forced colors use a focused system outline because shadows are suppressed. Buttons have 5px corners; button groups round only their outer ends.
- Use the 16px Carbon icons from `icons.tsx` (`Icon` in the DOM, `drawIcon` on canvas) instead of text glyphs such as ×, ↑, or ▾. Write run states with `statusSpec` labels and icons; nothing blinks.
- Apply the six text roles (table headings, buttons, agent messages, human messages, page titles, and normal text) through their CSS properties and the canvas table theme. All roles default to D-DIN Regular (400) in sentence case. Use regular weight for navigation, headings, status labels, controls and the wordmark; avoid hard-coded bold or selected-state weight changes. Apply the typography defaults once to existing installations while preserving size, case and other appearance preferences. Keep code and diffs monospace and case-preserving. Bundle fonts locally and retain their licenses; keep `font-src 'self'`.
- Get external data from snapshots and request reads with `poll`; do not start timers that fetch data. Use `useTicker` from `ticker.ts` for clock-only redraws, inside the smallest component that needs it, and report visibility with `setVisibility`.
- Keep Glide Data Grid imports in the renderer. Import its bundled CSS and pass theme colors resolved from the app's CSS variables, since the grid draws on a canvas; do not inject styles or weaken the Content Security Policy. Preserve row selection by session ID across sorting and data updates, and support clicking a row or pressing Enter on a cell to open its chat. The Actions cell opens its session's actions menu instead; keep that menu keyboard reachable.
- Build tables with `DataTable` from `data-table.tsx`, so every table shares Glide's search, header-menu filters, add row, and per-table settings. Save table preferences by stable column ID through `useTableView`; keep ad hoc column filters in memory. Named definitions and one active selection persist by table and database/project with `saved-filters.ts`; incompatible definitions must remain visible and unapplied. Use explicit column filter types so empty tables do not change their meaning.

- Give standalone buttons a 5px radius without a trailing-edge border effect. In button groups, round only the first control’s left corners and the last visible control’s right corners, with straight separators between controls. Main page surfaces have no outer border and retain 5px corners. Hover changes the fill without introducing a border. Inputs, checkboxes, radios, switches, scrollbar thumbs, dialog panels and overlays stay square; the logo and main Chat composer have upper-right chamfers. Standard button groups use 28px controls (30px overall), with 24px controls for compact groups. Table headers put the page title on the left and the control group on the right, wrapping on narrow screens. Button groups have no overlap or cutouts; give them a fine outer border, a restrained shadow, and white fills in Light and steel-gray fills in Dark. Use the standard Carbon checkmark. Focus outlines and glows follow the Focus highlight border preference, which defaults off; preserve keyboard focus behavior, validation baselines, filled resting controls and restrained overlay shadows.
- Table Settings opens a native modal with draft controls and a four-row fictional Glide preview. Reuse shared canvas styling and width calculations. Apply commits once; Cancel, Escape and close discard drafts. Reset is draft-only and removes the saved override when applied without further edits. Keep at least one data column visible, including when chart columns are turned off. Restore trigger focus, keep the header/footer visible, use two-column display toggles without row dividers, and discard drafts on workspace replacement. Put column visibility toggles in a closed-by-default dropdown above the orange dotted preview frame; Escape dismisses that dropdown before the modal. Scrollbars should remain subtle in both themes, with stronger hover contrast and system colors in forced-color mode.

- Default canvas gridlines off; preserve per-table line settings. Use white headers and rows in Light, steel-gray headers and rows in Dark, and resolved CSS colors in Glide. Preserve explicit labels when colors change or forced colors apply.
- Search and Messages use `useTranscripts` and its project-scoped cache. Bound concurrent history reads, deduplicate requests, expose partial failures/retry and discard stale project responses. No new IPC or telemetry capabilities are needed.

- Use one application footer across the full window bottom, with a clear top border. Polling controls live at the left; the persistent chat dock fills the remaining width. Keep page panels free of internal footer space and treat the footer as opaque during transparent-window hit testing.

- Keep the agent-message age above the footer’s top border. Dark footer surfaces are steel-gray; chat entries have visible side separators. Pointer reordering starts only on the six-dot Carbon draggable handle, never the chat label. Preserve keyboard reordering.

- Enclose repository identity and page navigation in one content-height sidebar surface without an outer border, with 5px corners and 6px inner padding. The tab list scrolls within the available height. Its filled interior, including gaps between buttons, stays opaque to transparent-window hit testing.

- Give every page-navigation item a locally bundled 16px Carbon icon to the left of its label, with 8px spacing. Icons inherit the tab’s state color and remain decorative to assistive technology; labels and alphabetical keyboard order remain authoritative.

- Settings exposes the app-wide orchestration provider and a checked, read-only Allow all actions without asking switch. Use the validated desktop bridge for saving and ACP connection probes; keep transient progress, success, failure and cancellation visible without explanatory copy.

- Require a saved, available orchestration provider before splash entry, including after renderer reloads. Reuse the Settings controls in the setup popup; cancelling or dismissing it leaves the splash blocked. Save failures and unavailable providers never unlock entry. Keep existing Start and recent-project Yes/No behavior after configuration, with equal-width No/Yes buttons in a responsive 360px-wide group and Yes on the right; ACP test success is optional.

- Nest New chat and labelled conversations beneath the expandable primary-sidebar Chat disclosure. Remember expansion; reveal externally selected conversations. Collapse never changes the conversation. Preserve independent drafts, transcripts and scroll positions; activity and failure indicators remain visible on background conversations. No secondary sidebar or standalone Files page.

- Present orchestration Chat as a conversation: right-aligned user messages, bordered assistant replies without repeated speaker labels, expandable Activity for thoughts/tools/permissions, and a persistent composer. Show a larger Code60 wordmark above New conversation only in the empty conversation view; keep the provider name at the right of the header. Keep progress visible with explicit text and a reduced-motion-aware 12px striped loading line inside the composer’s top border, with a matching 6px line inside the top edge of each connecting, working or stopping conversation entry in the primary sidebar; replace Send with Stop during a turn. Errors stay outside collapsed activity.

- Display automatic worker prompts as labelled activity, never as user messages. Show paused worker updates with a keyboard-reachable Resume updates control bound to the current chat ID. Label orchestrator-owned worker chats as allowing all actions. MCP contract descriptions must distinguish read-only tools from tools that change worker state.

- Group Configurations, Messages, Polling, Sessions and Worktrees beneath the expandable Tables sidebar item. Use the Carbon grid icon for Tables and every table child. Keep top-level pages and table children alphabetized. Remember expansion, reveal external table selections, and support arrow-key navigation and disclosure without changing the active page when collapsed.

- Group prompt templates beneath a collapsible System disclosure. Keep saved edits in this group, preserve drafts on collapse, omit per-prompt Built-in labels, and use borderless items with viridian hover and neutral gray selection.
- Files uses Headless Tree and the shared read-only Monaco inspector. Keep filesystem access scoped through `setFileContext` and refreshed by the main-process Files poll source. Bundle Monaco workers and languages locally; its generated style elements use the build nonce, with `style-src-attr` allowing its per-token positioning. Never permit inline scripts or remote assets. Clear file selection on project changes and hide Explorer and inspector outside Chat, preserving drafts and selection.

- Files uses borderless page and inspector surfaces, neutral selection and viridian hover. Keep file names and code case-preserving; resolve Monaco preview colors from the app theme tokens, including System appearance.

- The left sidebar header is a folder-icon project card. With no project, show Open a project with a dotted border and hatched fill; clicking opens the existing project modal, which can connect a database first when needed. A successful project selection shows a success toast and the folder name with a solid border and no hatching. Keep cancellation and errors in the modal, and disable switching while project runs are active.

- Chat File Explorer always opens the current project root. Route legacy Files, palette, Reveal in Files and Browse project files through Chat. Never select a worktree/private orchestration root; offer Open project when absent. Clear stale selections on project changes and discard stale reads.
- Automatically discovered/launched/reconstructed dock entries start minimized; only explicit navigation opens them. Share authoritative status icons/labels (including stopping and approvals). Target 400px popups, 480px default maximum height and a 40px footer, growing for enlarged controls. Preserve handle-only and keyboard reorder and full screen.
- Use per-conversation current-project owned worker IDs for aggregate activity, not the global worker list or process existence. Keep sendability and Stop tied to the orchestrator alone.
- Both chat interfaces use shared turn timing and Copy controls. Show dispatch-to-completion timing with outcomes; incomplete history stays explicitly unavailable. Use the local ticker only in small displays, without per-tick announcements or scroll/focus changes. Copy exact message source at invocation, await clipboard success, and offer actionable retry on failure. Keep the full runtime Code60 version in the primary-sidebar footer.
